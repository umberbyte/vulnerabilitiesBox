# バッチ04: 追加100変種

設計500変種のうち、既存307根本原因の代表ケースに属する**追加100変種**をソースへ接続しました。独立した採点単位である根本原因は307のままです。実装済みの設計変種は407、残りは93変種と30根本原因です。追加対象は [`batch4-selection.mjs`](src/cases/batch4-selection.mjs) に固定し、元の設計IDと根本原因の対応をテストで照合しています。

| 分野 | 追加変種 |
|---|---:|
| SQL構築 | 16 |
| ブラウザ表示・テンプレート | 17 |
| ファイル・経路・アーカイブ | 10 |
| 内部取得先 | 9 |
| 認証・認可・会員状態 | 29 |
| CSRF・CORS | 11 |
| 共有キャッシュ | 8 |
| **合計** | **100** |

既存のNode.jsアプリ、PostgreSQL、Redisを再利用しています。内部取得先はrun内のloopback HTTP fixtureで閉じ、ファイルの境界はコンテナ内の専用fixtureに限定しています。ソースは脆弱版 `V`、修正版 `F`、安全な類似入力用 `N` の切替を受け付けます。ただし、今回の追加変種について `N` の各境界入力およびV/Fの全件実動作成立は未検証です。

追加変種の切替例（コンテナ内管理者CLI）:

```text
node src/control.mjs variant-catalog
node src/control.mjs reset R0001 V batch4-2026 B0002
node src/control.mjs oracle
```

[`panel-batch-04-variants.json`](artifacts/panel-batch-04-variants.json) は100変種×V/F/Nの300セルで、**全件 `not_run`** です。既存の307代表ケース×V/F/Nの921セルの計画とは分離しました。再生成は `node src/runner/generate-variant-panel.mjs artifacts/別名.json`、実行は既存のpanel workerにそのJSONを指定します。実行時はセルの変種IDまでresetに渡し、計測ワークスペースも変種ごとに分けます。ZAP実行結果や検出率はこの計画からは発生しません。

この300セルは単一主体の基本プロファイルです。異なる利用者・管理者を順に使う境界、ブラウザでの実行イベント、順序依存のcache汚染は、別途専用の成立確認と複数主体の診断条件を要します。単一主体のZAPスキャンで見つからなかった場合に、直ちにツールの検出不能と採点しません。

このバッチで確認した範囲は、100件の設計ID照合、300セルの計画整合性、キャッシュとCSRFの一部境界に対する局所HTTPテスト、既存の公開契約テスト、および追加モジュールの構文です。当時はDocker CLIに接続できないと判断していましたが、その後Docker DesktopのLinux Engineへの接続を確認しました。このバッチ100件のPostgreSQL/Redisを伴う全件V/F/N受入は依然として未実施です。全体回帰はユーザーの指示に従い後でまとめて行います。210件版の630セル合格履歴は、現行407変種の合格を意味しません。

Burp Suite Professionalの比較はライセンス調達後に行います。顧客システムに対する診断や、ZAP・自作add-onの検出能力評価はまだ行っていません。
