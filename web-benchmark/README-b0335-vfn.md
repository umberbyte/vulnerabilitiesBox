# B0335 の V/F/N 成立確認

B0335 は HTTP と HTTPS の scheme を区別しない CORS 許可を再現する変種です。通常の Docker ネットワークでは、Chromium 154 が HTTP 攻撃元からローカルアドレスへの通信を CORS 評価前に遮断しました。さらに第三者 Cookie が遮断されると、ブラウザーの要求は認証されません。この二つの保護が有効な条件で、V の非公開データ読み取りが成立したと扱うことはできません。

専用の `compose.b0335.yaml` は、外部通信のない Docker 内部ネットワークに対象アプリと検証ブラウザーを置きます。対象のアドレスは `198.18.233.2` に固定し、検証コンテナ内の Chromium にだけ `BlockThirdPartyCookies=false` の管理ポリシーを読み込ませます。ホストのブラウザー設定は変更しません。別の Docker ネットワークが `198.18.233.0/24` を使用している場合は、重複を解消してから実行してください。

Windows では Docker Desktop を起動後、`web-benchmark` ディレクトリで `verify-b0335.cmd` を実行します。macOS/Linux では `sh verify-b0335.sh` を実行します。PowerShell のスクリプト実行ポリシーに依存しません。どちらもアプリと専用検証イメージをビルドし、B0335 の V/F/N だけを実行します。通常の `verify.cmd` や ZAP の測定条件へ、このブラウザーポリシーを持ち込みません。

結果は `artifacts/docker-smoke-b0335-vfn.json` に保存されます。2026-10-06 の記録では 3/3 条件が合格しました。V ではブラウザーの GET が認証済みの HTTP 200 応答を受け、HTTP 攻撃元に対する CORS 許可ヘッダーと非公開データの読み取りを確認しました。F/N では同じく HTTP 200 の認証済み応答を受けましたが、CORS 許可ヘッダーがなく、ブラウザーは読み取りを拒否しました。レポートには Chromium の版、ネットワークのアドレス、ポリシー・検証コード・Compose 定義の SHA-256、アプリと検証コンテナの実行ソース一致結果を記録します。最初の Compose 実行で F/N の HTTP 応答が Playwright の通常 API に現れなかったため、Chromium のネットワークイベントから確認し直した経過は `artifacts/docker-smoke-b0335-compose-first-20261006.json` に残しています。

`artifacts/coverage-inventory.json` は、この明示条件とソース一致が揃った B0335 の結果だけを個別 V/F/N 記録に算入します。500/500 という数は保存済みの個別成立記録の索引であり、全変種が同一ブラウザー設定・同一ソースで成立したことや、ZAP が検出したことを意味しません。B0335 を通常条件の ZAP/Burp 比較に採用する際は、ブラウザー側の遮断を別の評価軸として扱ってください。
